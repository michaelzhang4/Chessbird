# 🪵 Woodpecker Chess

A phone-first, offline, installable web app (GitHub Pages) for **Woodpecker Method** training:
curate a set of puzzles, then solve the *same* set across four ever-faster cycles to burn the
patterns in. Everything is tracked locally on your device.

- **Bring your own puzzles** — paste a Lichess CSV (or `FEN, moves` lines). Nothing is hardcoded.
- **The schedule, enforced** — Cycle 1: solve all in 7 days → 2-day break → Cycle 2: 4 days →
  1-day break → Cycle 3: 2 days → 1-day break → Cycle 4: 1 day. (~18 days / 2.5 weeks.)
- **Eligibility check** — sample 30 puzzles; aim for ≥75% first-try, no long calculation.
- **Tracks speed + accuracy** across cycles so you can see yourself getting faster.
- **chess.com-style green board**, works fully offline once installed.

## Run locally

```bash
npm install
npm run dev          # http://localhost:5173
npm test             # unit tests (chess logic, schedule, parsers, eligibility)
npm run check        # typecheck
npm run build && npm run preview   # production build + preview
```

## Add a puzzle set

Two ways to get sets into the app:

1. **In-app (no commit needed):** open **New set**, paste puzzles, **Parse & validate**, then
   **Save to My sets**. It lives in your browser only.
2. **Permanent library (committed):** in **New set**, press **Export JSON**. Drop the file into
   `static/data/sets/` and add an entry to `static/data/manifest.json`:

   ```json
   { "id": "my-set", "title": "My Set", "file": "sets/my-set.json", "count": 300,
     "ratingRange": [1300, 1700], "themes": ["fork", "pin"], "source": "lichess-csv" }
   ```

   Commit + push → it ships with the deployed app for one-tap "Begin".

### Where to get puzzles

The free **Lichess puzzle database** (<https://database.lichess.org/>) is the easiest source:
columns `PuzzleId,FEN,Moves,Rating,…,Themes,…,OpeningTags`. Filter by `Rating` (~1500) and
`Themes`/`OpeningTags`, take ~300 rows, and paste them into **New set** (auto-detected). For
opening/positional "best move" puzzles from any source, use the `FEN, uci uci …` format.

The bundled `sample-tactics.json` is regenerated by `node scripts/make-sample.mjs`.

## Deploy to GitHub Pages

1. Create a GitHub repo and push this project to `main`.
2. Repo **Settings → Pages → Build and deployment → Source = GitHub Actions**.
3. If your repo is **not** named `wood_pecker_chess`, update `BASE_PATH` in
   `.github/workflows/deploy.yml` to `/<your-repo-name>`.
4. Push — the workflow tests, builds, and deploys to `https://<user>.github.io/<repo>/`.

On your iPhone, open that URL in Safari and **Share → Add to Home Screen**. Installing makes
storage durable (Safari can otherwise clear site data after a week) and gives offline use.

> Your progress lives only on the device. Use **Settings → Export all data** now and then for a
> backup you can re-import.

## Tech

SvelteKit (static adapter) · TypeScript · Tailwind v4 · `@lichess-org/chessground` (board) ·
`chess.js` (rules) · Dexie/IndexedDB (storage) · native service worker (offline).

Piece set: **cburnett** (BSD, © Colin M.L. Burnett). Board theme inspired by the chess.com green.

## Project layout

```
src/lib/board/       chessground ↔ chess.js solving engine + theme
src/lib/puzzles/     parsers (Lichess CSV, FEN+moves), set build/export, zod schema

src/lib/eligibility/ 30-puzzle assessment + verdict
src/lib/db/          Dexie schema + repositories + backup
src/lib/services/    library (static/data) + training (ties schedule to storage)
src/routes/          Home · Set · Assess · Program · Solve · Stats · New · Settings
```
